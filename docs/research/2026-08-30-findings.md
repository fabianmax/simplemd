## 1. Hybrid live preview

### Naming and behavior

- **Typora** — "seamless live preview" / what-you-see-is-what-you-mean. Inline
  styles render when you finish typing them, block styles as you type or on
  Enter. Markers reappear when the cursor enters the formatted text. HTML blocks
  enter edit mode on cursor-inside or Cmd-click. 📄
  <https://support.typora.io/Quick-Start/>
- **Obsidian** — Reading view / Editing view → Live Preview (default) / Editing
  view → Source mode. `Cmd-E` cycles. 📄
  <https://obsidian.md/help/edit-and-read>

### Per-line vs per-block — the consequential choice

Two reference CM6 implementations diverge:

- **Per-cursor-element** (Obsidian/Typora style): reveal the inline span or block
  the cursor intersects. Centralized in one predicate,
  `shouldShowSource(state, from, to)`. 📄
  <https://github.com/blueberrycongee/codemirror-live-markdown>
- **Per-line**: raw syntax appears on the cursor's line. Stated invariants —
  *"every line has a stable height regardless of cursor position"*, *"lines never
  reflow when you click into them."* 📄
  <https://github.com/kenforthewin/atomic-editor>

**Chose per-line.** Per-block is worst for code-adjacent documents: a 40-line
fence or wide table is one block. Per-line eliminates the CLS/reflow bug class.
The atomic-editor post-mortem measured **~0.1 CLS per 10 cursor moves** with a
widget-per-block design — *"it felt like the UI was vibrating"* — and ~0.003
after the fix.

### CM6 element techniques 📄

| Element | Technique |
|---|---|
| Inline markers `**` `*` `~~` | `Decoration.mark({class})` + `max-width: 0 → 4ch` + opacity |
| Block markers `#` `-` `>` | `Decoration.line({class})` + `font-size: 0.01em → 1em` |
| Code fences | `Decoration.replace({widget})`, `CodeBlockWidget extends WidgetType` |
| Tables | lezer `"Table"` node → `TableWidget` via markdown-it, `ignoreEvent() = true` |
| Images | `ImageWidget`, load/error fallback, click dispatches `goToLink` effect |
| Math | `MathWidget` + KaTeX, `Map` cache, `requestIdleCallback` prerender queue |
| Parse | `syntaxTree(state)` over lezer-markdown |
| State | one `StateField<DecorationSet>` per element type; `deco.map(tr.changes)` on selection-only transactions |

### Three landmines 📄

1. **`atomicRanges` eats text.** Marijn Haverbeke: *"that's what `atomicRanges`
   does — causes the whole range to be treated as a single thing for the purpose
   of cursor motion and backspacing."* One backspace deleted a whole span.
   <https://discuss.codemirror.net/t/hide-markdown-syntax/7602>
2. **`display:none` breaks cursor placement.** `obsidian-codemirror-options` had
   to move to `font-size: 1px` + negative letter-spacing.
   <https://github.com/nothingislost/obsidian-codemirror-options>
3. **Drag-selection flicker.** Gate rebuilds on a dragging flag; capture-phase
   `pointerdown` (bubble is too late — `lang-markdown`'s own handler runs there),
   release ~100 ms after `pointerup`.

Also: peer-dep every `@codemirror/*` package — two copies of `@codemirror/state`
silently break state-field identity checks. 📄

### User complaints 📄

- Toggling a task checkbox returns the cursor to its previous location —
  <https://forum.obsidian.md/t/cursor-jumps-to-previous-location-when-changing-task-status-in-live-preview-on-mobile/96385>
- **Tables are the worst offender**: broke vim navigation
  (<https://forum.obsidian.md/t/vim-support-more-commands-in-live-preview-tables/73992>)
  and row/column moves are a RAM leak that makes the app nonresponsive
  (<https://forum.obsidian.md/t/re-rendering-live-preview-reading-mode-tables-by-moving-lines-table-rows-or-columns-shortcut-is-extremely-ram-intensive-and-a-memory-leak-that-leads-to-nonresponsive-app/116711>)
- **Inconsistency is the meta-complaint.** Typora issue #1317 lists nine leaks:
  footnotes show markup, custom anchors show HTML, emoji shows both glyph and
  shortcode, links auto-expand.
  <https://github.com/typora/typora-issues/issues/1317>

### The round-trip trap — why the block-editor family is out 📄

Editors that parse → model → re-serialize rewrite the whole file. GitLab's
WYSIWYG rollout produced *"a high volume of changes… especially on long pages"* —
renumbered lists, changed link syntax, altered fences.
<https://gitlab.com/groups/gitlab-org/-/epics/4554>
Vrite (ProseMirror) needs explicit transformers and still drops inline JSX.
<https://vrite.io/blog/wysiwyg-for-mdx-introducing-vrite-s-hybrid-editor/>

**Disqualifies ProseMirror / Tiptap / Lexical / BlockNote / Milkdown as the core.**

### Native alternatives (if the CM6 lean is ever revisited) 📄

| Option | Verdict |
|---|---|
| [swift-markdown-engine](https://github.com/nodes-app/swift-markdown-engine) | AppKit + TextKit 2, Apache 2.0, does incremental per-keystroke restyling and marker hiding. **No viewport virtualization** — "small-to-medium content" only |
| [STTextView](https://github.com/krzyzanowskim/STTextView) | TextKit 2, decorations, plugins. **GPL v3 / commercial dual-license** — a business decision |
| [MarkEdit](https://github.com/MarkEdit-app/MarkEdit/wiki/Philosophy) | Ships CM6 in a WKWebView inside a native AppKit shell. **The pattern to copy** |
| [Editorio](https://editorio.crncevic.org/) | AppKit + NSTextView + custom tokenizer. Sub-100 ms launch, ~40 MB RAM — proof the native path meets the startup bar |

## 2. External file change handling

| Tool | Behavior 📄 |
|---|---|
| **VS Code** | Silent auto-reload when buffer is clean; conflict dialog only on save when dirty. Silence caused real loss — a Dropbox conflict-rename [restored a user's editor to an earlier save](https://github.com/Microsoft/vscode/issues/41250). Open request to [skip the prompt when disk and buffer are byte-identical](https://github.com/microsoft/vscode/issues/241381) |
| **Zed** | Worst. Full-screen modal, hit *hundreds of times per day*, user picks overwrite 100% of the time — closed **not planned** ([#42108](https://github.com/zed-industries/zed/issues/42108)). Stale content with `Error { kind: WatchNotFound }` — watcher doesn't cover files outside project dirs ([#48439](https://github.com/zed-industries/zed/issues/48439)). No staleness detection, so its own agent clobbers external edits ([#53590](https://github.com/zed-industries/zed/issues/53590)) |
| **Typora** | [#6578](https://github.com/typora/typora-issues/issues/6578) is simplemd's product brief: *"This makes working with AI agents that are modifying plan files impossible, as the focus jumps between Typora windows."* Plus [unreliable auto-refresh](https://github.com/typora/typora-issues/issues/894), [mistaking its own saves for external edits](https://github.com/typora/typora-issues/issues/1401), [detect-and-prompt open since 2017](https://github.com/typora/typora-issues/issues/1011). [#5209](https://github.com/typora/typora-issues/issues/5209) proposes the right design |
| **Obsidian** | Open note shows stale content until you navigate away and back. Reporter uses Claude Code; a replier uses Codex. No official fix; community workaround polls the whole vault every 8 s — <https://forum.obsidian.md/t/obsidian-doesnt-reload-the-current-file-when-it-is-changed-outside-of-obsidian/114185> |
| **CotEditor** | Second-order bugs: 7.0.7 fixed alerts displaying twice, and the app hanging when a document auto-updated while an alert was shown |

**Nobody handles this well.** Closest to right is VS Code's clean-buffer silent
reload, but it lacks scroll/cursor preservation and hash-gating.

### Atomic writes ✅

Claude Code's `Edit` and `Write` both change the inode
(282226906 → 282226912 → 282226955): write-temp + `rename()`. A 2 ms directory
poll never observed a temp sibling, missing path, or truncated read — the swap is
atomic. **No partial-read defense needed.** But an inode-bound watch dies.

### Watcher fixes 📄

1. Watch the **parent directory**, filter by filename, debounce, stat, re-read.
2. kqueue + re-arm: mask `NOTE_DELETE | NOTE_RENAME | NOTE_WRITE | NOTE_EXTEND |
   NOTE_ATTRIB | NOTE_REVOKE`; on delete/rename close the fd, re-`open()` the
   **path**, retry briefly (there is a window where the path does not exist).
3. `kFSEventStreamCreateFlagWatchRoot` for `RootChanged`.

`NSFilePresenter` confirmed useless — Apple, verbatim: *"Your presenter objects
are not notified about changes made directly using low-level read and write calls
to the file. Only changes that go through a file coordinator result in
notifications."*
<https://developer.apple.com/documentation/foundation/nsfilepresenter>

## 3. Diff / review UX

**Core problem:** agents rewrite whole files and reflow paragraphs. A line-level
diff against reflowed prose is unreadable — every paragraph reads as fully
deleted and fully re-added. Needs **word-level** diffing (`git diff --word-diff`,
difftastic, delta are the CLI precedents).

### What the built-in agent viewers do 📄

**Codex Desktop** is preview-only, and its users are requesting exactly simplemd's
feature set — rendered↔source toggle, unsaved indicators, *"refresh the rendered
view automatically or show a clear stale/out-of-date indicator"*, *"preserve
scroll position across edits, refreshes, and thread navigation"*, and mapping a
rendered selection back to Markdown line ranges.
<https://github.com/openai/codex/issues/28644>

**Claude Code**'s gap, from its own users: plan files land in *"an unfindable
directory with auto-generated names"*; clicking a `.md` link shows source, not
rendered output. Closing line, which is simplemd's positioning statement:

> *"it makes Claude Code feel like it's optimized for 'agents writing code' and
> not for 'humans reading what agents produced.'"*

<https://github.com/anthropics/claude-code/issues/55142>

### Patterns worth stealing, ranked 📄

1. **Marked's "Scroll to Edit"** — on refresh, *"scrolls directly to the first
   changed area of the file when it updates."* Cheapest high-value feature found.
   Marked also watches a folder and surfaces the most recently modified file —
   one gesture for `~/.claude/plans/`.
   <https://markedapp.com/help/Using_Marked_with_Agentic_Coding.html>
2. **"Since I last looked" baseline.** Snapshot on tab focus-loss, show
   "3 sections changed" with gutter bars and n/N navigation. **No incumbent does
   this** — Marked's baseline is the last *save*.
3. **MarkViewer's diff banner** — auto-detects external AI modification, offers
   Accept / Dismiss, non-modal, in-document. <https://markviewer.com/>
4. **PullMark's rendered word-level diff** — `pullmark --diff plan.md`.
   <https://pullmark.app/uses/agents/>
5. **Rendered diff over source diff** — mark insertions/deletions inline,
   Google-Docs-suggestion style, with a source-diff toggle.
6. **md-redline's MCP round-trip** — the agent calls `mdr_request_review` and
   *blocks* until the human comments. Right shape, v2 material.
   <https://github.com/dejuknow/md-redline>

### Traps 📄

- **Never store review state in the file.** iA Writer's Authorship writes author
  metadata into the `.md`, visible in every other editor. md-redline's HTML
  comments require the agent to remember to delete them. Use a sidecar keyed by
  path + hash.
- **Don't use a git commit as the baseline** — agent plans are often untracked.
- **Never line-diff prose.**

## 4. Markdown pipeline benchmarks 📊

Node/V8. **Tauri runs JavaScriptCore — re-measure before designing around these.**

| corpus | markdown-it 15 | marked 18 | lezer+GFM | micromark 4 | remark full |
|---|---|---|---|---|---|
| 202 KB / 12.8k lines | 27.1 ms | 18.1 ms | 17.1 ms | — | **337 ms** |
| 583 KB / 30.8k lines | 67.4 ms | 43.9 ms | 53.0 ms | 669 ms | **1,217 ms** |
| 1.76 MB / 92.5k lines | 222 ms | 131 ms | 152 ms | 2,162 ms | **6,345 ms** |

**remark/unified is 18-29x slower and degrades superlinearly.** Root cause
isolated: not the GFM extensions (remark-parse without GFM is still 554 ms vs
64.5 ms) — the mdast for that file serializes to **10.1 MB of JSON**, a 17x
blowup from `position` objects that cannot be disabled. micromark direct is also
out (669 ms); wooorm's own README says *"You probably should use remark."*

### Architectural findings 📊

- **Block boundaries from the lezer tree.** Blank-line splitting is silently
  wrong (loose list → 3 tight lists; reference links break). Correct splitting:
  full re-render 67.4 ms → **6.9 ms**. Splitting via `md.parse()` gains almost
  nothing (63.3 ms) because tokenizing is 59.6 of the 67.4 ms. Keep
  `env.references` shared and make the reference set part of the cache key.
- **Workers: ship HTML strings, never ASTs.** Cloning markdown-it's token array
  costs **275.7 ms** — 4x more than parsing from scratch. mdast: 135.7 ms. The
  1.09 MB HTML string: **0.1-0.5 ms**. Encode line mapping as `data-line`
  attributes, where it travels free.
- **Don't virtualize the preview — diff it.** VS Code's preview re-renders to a
  string and applies with **morphdom** (`childrenOnly`, skip subtree when
  `areNodesEqual`), preserving scroll, `<details open>`, image load state and
  already-rendered mermaid SVGs. Virtualizing breaks find-in-page, `#heading`
  anchors, and scroll sync. Use `content-visibility: auto` +
  `contain-intrinsic-size` instead.
- **Viewport-scoped highlighting is mandatory.** A corpus with 1,248 fenced
  blocks: **~8.7 s** to Shiki the whole document vs **<20 ms** for one viewport.

### Library notes ⚠️ (versions unverified by me)

- **Shiki v4** (`shiki@4.4.3`). JS RegExp engine init 1.0 ms vs 55.2 ms for WASM
  oniguruma; WASM wins throughput (7.05 vs 9.61 ms/block) — irrelevant once
  viewport-scoped. Do **not** use `@shikijs/langs-precompiled` (active warning,
  issue #918).
- **mermaid**: npm's default export is `dist/mermaid.core.mjs` (52 KB) which
  code-splits into ~103 per-diagram chunks — `import('mermaid')` under Vite costs
  ~11 KB entry + ~150 KB core + only the diagram types used. The UMD build is
  976 KB gz; don't use it.
- **mermaid + DOMPurify collision:** DOMPurify drops `<foreignObject>` children
  **even with `ADD_TAGS:['foreignObject']`**, and mermaid's flowchart renderer
  uses `foreignObject` for HTML labels by default. "Render then sanitize the SVG"
  **wipes your diagrams.** Use a sandboxed iframe, or `htmlLabels:false`.
- **Use `mermaid.render(id, text)`, never `run()`**, and content-hash the id —
  `removeExistingElements` does `getElementById(id).remove()`, so a colliding id
  deletes whatever else owns it. Reference: `mjbvz/vscode-markdown-mermaid`.
- **`markdown-it-task-lists@2.1.1` has a module-scope state bug**
  (`disableCheckboxes` is a module-level `var` mutated per-instance), CJS-only
  since 2018. Use the `@mdit/plugin-*` family. markdown-it 15 bundles its own
  types — drop `@types/markdown-it`.
- **Sanitization:** adopt rehype-sanitize's *schema* (59 tags, no `data:`
  protocol, `clobberPrefix: 'user-content-'`), not its pipeline (755 ms + drags
  in remark). Port it into a DOMPurify config. `rehype-sanitize@6.0.0` hasn't
  shipped since 2023-08-26, and `hast-util-sanitize`'s `transform()` silently
  deletes `raw` nodes. On DOMPurify's 2026 advisories: 9 of 15 involve
  `IN_PLACE`, hooks, or predicate-form `ADD_TAGS`; the unpatched one states
  *"Not affected: String-input."* **Use the plain string path with no hooks.**
- **Footnotes are absent from `@lezer/markdown`** and from npm. The one
  implementation is `erykwalder/lezer-markdown-obsidian` (8 stars, last pushed
  2023-12-27, MIT). **Vendor it, don't depend on it.** ~90 lines: an inline
  parser + a `LeafBlockParser`. That repo also has Comment, Hashtag,
  InternalLink, Mark and YAMLFrontmatter as a reference set.
- **lezer correctness caveat**, from its README: *"in order to be single-pass and
  incremental, it doesn't validate link references, so it'll parse `[a][b]` as a
  link, even if no `[b]` reference is declared."*

## 5. Shell, security, distribution

### Tauri security 📄

- **`window.__TAURI_INTERNALS__.invoke` is defined unconditionally**, regardless
  of `withGlobalTauri`. `__TAURI_INVOKE_KEY__` defends against *cross-frame*
  confusion, **not same-frame XSS**. Any script in a webview can invoke any
  command that webview is permitted.
- **The fix is also Tauri's genuine edge:** run the preview in its own webview
  with `permissions: []`. XSS in rendered agent markdown then finds nothing to
  call. Electron cannot express this boundary as cleanly. Relevant because the
  threat model is real: *an agent summarizes an untrusted README and it lands in
  a file you open.*
- **Tauri v2 ships no CSP by default** — `pub csp: Option<Csp>`, no default. Docs
  confirm CSP *"only functions when explicitly enabled."*
- Honest counterweight: **`RETURN_TRUSTED_TYPE` is a no-op on WKWebView**
  (Trusted Types is Chromium-only). A real Tauri-vs-Electron security regression.

### CLI shape under sandboxing 📄

**argv grants nothing.** Apple DTS (Quinn): *"The sandbox system does not do
anything special with command-line arguments… it does not look at your
command-line arguments and extend your sandbox to grant you access to those
directories."* <https://developer.apple.com/forums/thread/724467>
`com.apple.security.inherit` doesn't rescue a sandboxed helper either — Terminal
isn't sandboxed, so there is nothing to inherit.
<https://developer.apple.com/forums/thread/13901>

Launch Services document-opens **do** grant, via a sandbox extension token
(`sandbox_extension_issue_file` → `sandbox_extension_consume`).
<https://bdash.net.nz/posts/sandboxing-on-macos/>

| CLI shape | Sandbox-safe |
|---|---|
| `open -a simplemd file.md` (odoc → `application(_:open:)`) | ✅ |
| `open -a simplemd --args file.md` | ❌ `man open`: *"These arguments are not opened or interpreted by the open tool"* |
| CLI reads `argv[1]`, sends path over private IPC (Zed's design) | ❌ no extensions issued |

**Marked 2** — sandboxed, on the MAS, closest analogue to simplemd — ships:
```sh
#!/bin/sh
if [ $1 ]; then open -a "Marked 2" $1; else open -a "Marked 2"; fi
```
<https://jblevins.org/log/marked-2-command>

### Packaging 📄

- **Notarization cannot staple standalone binaries** — the CLI must live inside
  the `.app`. `xcrun notarytool submit --wait` then `stapler staple App.app`;
  `altool` dead since 2023-11-01.
- **BBEdit's cask is the template** — ships MAS *and* direct, with
  `binary "#{appdir}/BBEdit.app/Contents/Helpers/bbedit_tool", target: "bbedit"`.
  Ghostty, iTerm2 and Typora ship no `binary` stanza at all.
- **App Translocation:** since 13.3.1 the only reliable avoidance is removing
  `com.apple.quarantine`. Homebrew clears the translocation bit for casks, so
  cask installs largely dodge it. (`--no-quarantine` may be removed in recent
  Homebrew — ⚠️ verify.)
- **Security-scoped bookmark traps:** URLs from open/save panels and Dock drags
  arrive *already started* (call `stop`, not `start`); persisted bookmarks are
  the reverse. App-scoped bookmarks are signature-bound and **cannot be shared
  with a sibling CLI**. Leaking access is a hard failure.
- **MAS review pushes back on the CLI feature itself.** Verbatim rejection:
  *"Guideline 2.3 – Performance … Grant access to Macintosh HD … It will be
  necessary to remove this functionality from the app."* (Fix: default the
  `NSOpenPanel` to `~`, not `/`.) Panic's Transmit page states Open In Terminal
  *"was removed at Apple's request."*
- **Indie precedent:** BBEdit left the MAS ~2014, returned sandboxed at 12.6 with
  claimed identical functionality. Panic's Coda never made it (*"a sandboxing
  worst-case scenario… we've run out of time"*); Transmit 5 returned at the cost
  of Transmit Disk and Open In Terminal. Bare Bones' escape hatch is a single
  "Allow…" button granting the startup disk via `NSOpenPanel`.

## 6. Open risks, ranked

1. **CM6 with thousands of block-replace widgets on a 50k-line file is
   unmeasured** — no public data, and it is what full live-preview implies.
   Prototype this *and* the WKWebView feel test in week one; same experiment.
2. **All benchmarks above are Node/V8**, not JavaScriptCore.
3. **DOMPurify's real WKWebView throughput** — the 605 ms/1 MB figure is jsdom,
   ~64% of it jsdom's own parser, which is native in a webview.
4. **`markdown-it-footnote` looks quadratic** — 64.5 ms → 337.9 ms on a
   footnote-dense doc. Benchmark against a real corpus.
5. **Whether FSEvents honours sandbox extensions for a user-granted folder** is
   ⚠️ unverified with no Apple statement either way. `FSEventStreamCreate`
   documents `pathsToWatch` as *"a path to a directory"*, but Quinn notes an
   open-panel grant *"does not apply to the directory containing that file."*
   Test before any MAS commitment.
6. **Every Rust mermaid crate is unverified**; `mermaid-little`'s repo 404s.
   Ship JS mermaid.
7. **No published 2025/2026 markdown-parser benchmark exists** — every number
   here is ours.
