## Slice 1 — the code font reads as code

### Diagnosis

Two causes, both confirmed in the source:

- `src/styles.css:8` — `--mono: ui-monospace, "SF Mono", Menlo, monospace`.
  On macOS `ui-monospace` resolves to **SF Mono**, which shares its skeleton
  with the `-apple-system` body font (`styles.css:35`). So the code font is
  literally a sibling of the prose font.
- It is then rendered *smaller* everywhere: `0.92em` for fenced lines
  (`styles.css:62`) and `0.92em` for inline code (`src/editor/highlight.ts:17`,
  `t.monospace`). Mono faces also have a smaller x-height than SF, so equal
  `em` already looks smaller — `0.92em` compounds it.

That is exactly the reported symptom: *"seems to be just smaller — which is
also weird"*.

### Change

- `styles.css:8` → `--mono: Menlo, "SF Mono", ui-monospace, monospace;`
  Menlo is a DejaVu/Bitstream Vera derivative: different skeleton, different
  proportions, visibly *not* SF. Ships on every macOS — zero bytes, zero
  startup cost, which is why it wins over bundling a webfont.
- `styles.css:62` `.lp-code-line` — drop the `font-size: 0.92em` **entirely**,
  do not set it to `1em`. See the correction below.
- `highlight.ts:17` `t.monospace` font-size `0.92em` → `0.95em`.

### Correction found while implementing

The two sizes were **compounding**, which is the real reason fenced code read
so small. `@lezer/markdown` tags `InlineCode` and `CodeText` with the *same*
`t.monospace` tag (`@lezer/markdown/dist/index.js:1974`), so inside a fence the
`0.92em` on the line and the `0.92em` on the span multiplied out to `0.85em`.
Removing the line-level size leaves one authority for code sizing — the
highlight style — at `0.95em` for both inline and fenced code. Documented in a
comment at `styles.css:60` so it does not get re-added.

That same shared tag also **rules out the inline-code chip** the plan proposed:
a background/padding rule on `t.monospace` would tint every fenced line too, on
top of the `.lp-code-line` band. There is no DOM-level distinction between the
two — both are spans with the same generated highlight class — so the chip
would need a new decoration in `decorations.ts`, which only runs in preview
mode and per-line reveal state. That means the tint would blink off whenever
the cursor entered a line, which is worse than no tint. Dropped; the face swap
and size parity are what the request actually asked for.

### Constraint to preserve

`highlight.ts` opens with the stability rule: syntax styling is applied in
**both** preview and raw mode so heights never change when markers reveal.
Every change above is mode-independent, so the rule holds. Code lines becoming
taller than prose lines is fine — the invariant is *stable per line*, not
*uniform across lines*.

### If Menlo still reads too close

Fallback, in order: (a) JetBrains Mono as a subset woff2 in `dist/`, ~100 KB,
costs a font load on every launch — weigh against the startup budget;
(b) keep Menlo and push differentiation into the band (`--band`) and letter
spacing instead of the face.

### Tests

None — this is a variable swap with no logic. Covered by the visual pass below.

## Slice 2 — text scales with the window

### Diagnosis

`src/styles.css:44-48`:

```css
.cm-editor .cm-content {
  max-width: 76ch;
  font-size: 15px;   /* fixed */
}
```

The font never changes, so enlarging the window only grows the left and right
margin. The measure is `76ch`, which is font-relative — meaning it is *already*
wired to scale, it just has nothing to scale with.

### Change

- `styles.css:47` → `font-size: clamp(14px, 0.375vw + 12px, 19px);`
  That is 15px at an 800px-wide window, 16.5px at 1200px, 18px at 1600px,
  capped at 19px. Because the measure is `76ch`, the column widens in lockstep
  — one change gives both "text scales" and "more room for tables".
- `styles.css:70` `.lp-table table` font-size `0.95em` → `1em`; cell padding
  `3px 10px` → `6px 12px` (`styles.css:72`).
- `styles.css:68` `.lp-table` → add `overflow-x: auto;` so a table wider than
  the measure scrolls instead of crushing its columns. macOS overlay
  scrollbars take no layout height, so the widget's measured height is
  unchanged.

### Deliberate choice: `vw`, not container units

`cqi` on `.editor-host` would track the *editor pane* rather than the window,
which sounds more correct but means the text resizes every time the file
browser is toggled. Text jumping on a panel toggle is worse than text not
reacting to it. Use `vw`.

### CM6 gotcha

Font-size changes invalidate CodeMirror's cached line heights and measured
character width (which `EditorView.lineWrapping` depends on).

**Verified, no app-side code needed:** CM6's `DOMObserver` registers a
`window.resize` listener that calls `view.requestMeasure()` on a 50 ms throttle
(`@codemirror/view/dist/index.js:7206` and `:7494`). Because the font here is
`vw`-based it only ever changes *during* a resize, which is exactly when CM6
remeasures — and the throttle re-fires every 50 ms through a continuous drag
rather than waiting for it to end. No `requestMeasure` call in `app.ts`.

### Tests

None meaningful — keep the scaling entirely in CSS so there is no JS to test.
If it ends up needing a JS helper, that is a signal the approach is wrong.

### Optional phase 2 (only if tables still feel cramped)

Let tables break out of the `76ch` measure: hoist the measure to a custom
property on `.cm-content` and give `.lp-table` a negative inline margin bounded
by the available gutter. Not worth the complexity unless slice 2 proves
insufficient — decide after looking at it.

## Slice 3 — file explorer: icons, tree, in-window toggle

### 3a. Row markup

Today each row is a single div whose `textContent` is `"▸ " + name`, indented
with an inline `paddingLeft` (`src/browser.ts:96-100`). That is why it looks
unfinished: the chevron is text, and there is no structure to style.

Replace with three children per row:

```
<div class="browser-row" data-path data-kind>
  <span class="browser-chevron"></span>   <!-- dirs only, rotates on expand -->
  <svg class="browser-icon">…</svg>
  <span class="browser-name">…</span>
</div>
```

- Icons are **inline SVG** from a small `icon(kind)` helper in `browser.ts` —
  no icon font, no dependency. Kinds: `dir`, `md`, `image`, `code`, `file`.
  Keep it to five; this is decoration, not a file-type registry.
- `data-kind` on the row makes the whole thing headless-testable.
- Chevron rotation via a `.browser-open` class + CSS `transform`, not by
  rewriting `textContent`.

### 3b. Tree structure

Move indentation out of inline styles: each nested level gets a
`.browser-level` wrapper carrying the indent and a 1px left guide rule
(`color-mix(currentColor 10%)`), so nesting is visible as a line rather than as
guessed whitespace. Rows then need no inline `style`.

### 3c. Colors and density

Minimal, following what is already there: `.md` files at full `--fg`, other
files at `--fg-dim`, directories at `--fg` semibold, accent reserved for the
active file. Row font-size `12.5px` → `13px`, line-height `1.35` → `1.5`.
Icons inherit `currentColor` so dark mode needs no second rule.

### 3d. Open it from the window

- Add a pinned leading button to the tab strip (`app.ts:51`), left of the tabs:
  a sidebar glyph, `title="Toggle file browser (⌘⇧B)"`.
- Extract the body of the `toggle-browser` menu branch (`app.ts:242-245`) into
  `private async toggleBrowser()` and have both the menu and the button call
  it. The menu item and accelerator stay exactly as they are.
- **Latent gap to fix here:** `BrowserPanel.setRoot` is what builds the header
  (`browser.ts:51-72`), so when there is no root the panel shows only the hint
  *"Open a file to root the browser"* — with no way to choose a folder, because
  the `…` button lives in that header. Add a "Choose folder…" button to the
  empty hint (`browser.ts:76-81`), reusing `ipc.pickFolder`.

### Tests (`tests/browser.test.ts`)

These assertions **will break** and must be updated — they read the chevron out
of `textContent`:

- `["▸ sub", "plan.md"]` → assert `.browser-name` text plus `data-kind`
- the expand/collapse test's `row.textContent === "▾ " + name` → assert the
  `.browser-open` class instead

Add:

- `data-kind` is `md` / `file` / `dir` for the right entries
- nested levels render inside a `.browser-level` wrapper at the right depth
- the empty hint exposes a folder-picker button, and clicking it calls
  `ipc.pickFolder`
- lazy-fetch invariants (fetch once per level, no recursion) must still hold —
  do not weaken those; they are the non-goal guard.

App-level: a test that the tab-strip button and the `toggle-browser` menu id
both reach `toggleBrowser`.

### Implementation notes

- **Icons landed in a new `src/icons.ts`**, not inside `browser.ts`. The tab
  strip needs the same SVG boilerplate for its sidebar glyph, and duplicating
  it in two modules to avoid one small file would have been the worse trade.
- **The tab strip is now always visible** (it was hidden at zero tabs). It
  holds pinned chrome rather than only tabs, and a toggle that disappears
  exactly when you most need the browser — no file open, looking for one —
  fails the requirement it was added for.
- **The App-level test was not written.** There is no `app.test.ts` and no
  harness for `App` (its constructor builds an `EditorView` and wires the whole
  Tauri IPC surface), so standing one up for a two-line delegation is out of
  proportion to this slice. The single `toggleBrowser()` path is enforced by
  the type checker instead. If `App` ever needs tests for its own sake, this
  belongs in the first batch.

## Sequencing

1 → 2 → 3. Slices 1 and 2 are the same file and should be judged together in
one look at a real document; slice 3 is independent and can land separately.

Each slice ends runnable. After each: `npm test` (69 vitest) and `cargo test`

## Verification

Headless tests cover slice 3 only. Slices 1 and 2 are visual by nature, so the
check is explicit:

- open a code-heavy plan file and a table-heavy one
- at three window widths (~800 / 1200 / 1800 px): text scales smoothly, the
  measure widens with it, tables are legible
- drag the window slowly across that range: no cursor drift, no reflow jump
- toggle preview (⌘E) in both: heights must not change between modes
- both themes

## Risks

- **Font-size + CM6 measurement** is the only real one (slice 2). The failure
  mode is subtle — cursor coordinates drifting from the visual caret — so test
  by dragging the window, not by resizing in one jump.
- **Slice 3 touches the browser's row rendering**, which is where the
  lazy-fetch guarantees live. Keep `renderLevel`'s fetch logic untouched;
  change only what it builds.

## Deferred: the settings window

`PLAN.md` proposes a settings window whose first entry is "should the file
explorer be open by default". CLAUDE.md: *"One good default beats a settings
pane. Config surface stays near zero."* The zero-config version of that feature
is to persist the explorer's last open/closed state and restore it on launch —
same outcome, no window, no settings file, no second home for state. Suggested
as a follow-up one-liner on top of slice 3, with the settings window revisited
only when a second setting actually exists.
